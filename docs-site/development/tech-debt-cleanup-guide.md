# 技术债清理指南

## 概述

本文档提供技术债识别、清理和预防的指南。

## 技术债识别

### 常见技术债类型

1. **废弃代码**
   - 未被导入的文件
   - 标记 @deprecated 的代码
   - 被 V2 版本替代的旧代码

2. **临时文件**
   - backup_*.txt
   - *_temp.* 文件
   - 调试脚本

3. **架构违规**
   - 新代码不在 v2 目录
   - 混用新旧架构
   - 未遵循目录规范

4. **文档债务**
   - 过时的 API 文档
   - WIP 文档长期未清理
   - 缺失的类型文档

### 识别工具

```bash
# 查找未被导入的文件
npx ts-unused-exports tsconfig.json

# 查找临时文件
find . -name "*_temp.*" -o -name "backup_*"

# 查找 @deprecated 标记
grep -r "@deprecated" src/
```

## 清理流程

### 阶段 1：识别
1. 运行识别工具
2. 生成清理清单
3. 评估风险

### 阶段 2：验证
1. 确认无引用
2. 检查测试覆盖
3. 评估影响范围

### 阶段 3：清理
1. 创建归档
2. 删除文件
3. 更新引用

### 阶段 4：验证
1. 运行测试
2. 功能验证
3. 提交变更

## 清理检查清单

### 清理前
- [ ] 确认文件未被使用
- [ ] 创建归档备份
- [ ] 评估影响范围
- [ ] 准备回滚方案

### 清理后
- [ ] 所有测试通过
- [ ] 功能验证完成
- [ ] 文档已更新
- [ ] Git 提交清晰

## 预防措施

### 开发规范
1. 新功能必须在 v2 目录
2. 禁止创建备份文件
3. 及时清理 WIP 文档
4. 代码审查检查架构

### 定期维护
- 每月检查未使用文件
- 每季度更新文档
- 每年清理归档目录

### 工具辅助
- ESLint 规则检测违规
- Husky 钩子预防提交
- CI 检查架构规范

## 归档策略

### 归档时机
- 代码废弃超过 30 天
- 功能完全迁移到新版本
- 文档过时但有参考价值

### 归档格式
```
archive/
├── legacy-files-YYYYMMDD.tar.gz
└── README.md
```

### 归档内容
- 源代码文件
- 说明文档
- 变更历史
