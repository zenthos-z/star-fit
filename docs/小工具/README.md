# 小工具集合

本目录包含各种实用的小工具。

## 工具列表

### 1. 运动库自动补全修正工具 (`exercise-library-fixer.html`)

一个智能的运动库数据修复工具，使用AI自动识别并补充或修正运动库中的缺失和错误信息。

#### 功能特点

- **智能扫描**: 自动检测运动库数据中的空值、错误值和测试标记
- **AI修复**: 支持多种AI提供商（OpenAI、Gemini、OpenRouter）自动补充缺失信息
- **进度提示**: 实时显示修复和生成教程的进度，包含进度条和详细信息
- **单独修复**: 支持单个运动独立修复，灵活控制修复流程
- **标准数据**: 身体分类和肌肉群使用项目标准值，确保数据一致性
- **自定义提示词**: 支持自定义教程生成提示词，满足个性化需求
- **教程生成**: 为每个运动生成详细的HTML格式教程（动作作用、发力心法、注意事项、常见错误）
- **可展开视图**: 点击运动卡片可展开查看详细的修复结果和教程内容
- **批量处理**: 支持批量修复多个运动项目
- **数据导出**: 修复完成后可导出标准格式的JSON数据
- **ZIP支持**: 直接导入导出的运动库ZIP文件
- **实时统计**: 显示总数、问题数和已修复数

#### 检测的问题类型

1. **空值检测**
   - 运动名称为空
   - 分类为空
   - 内容描述为空
   - 运动类型为空
   - 身体分类为空
   - 肌肉群信息缺失
   - 设备要求为空
   - 难度为空

2. **错误检测**
   - 名称包含测试标记（如"-E2E"）

3. **数据完整性检测**
   - 肌肉群结构不完整
   - 设备列表为空

#### 使用方法

##### 1. 打开工具

直接在浏览器中打开 `exercise-library-fixer.html` 文件。

##### 2. 配置AI提供商

在"配置"区域选择AI提供商：

**OpenAI**:
- 输入OpenAI API Key（格式：`sk-...`）
- 选择模型（推荐GPT-5.2或GPT-4.1）

**Gemini**:
- 输入Gemini API Key（格式：`AIza...`）
- 选择模型（推荐Gemini 3 Pro或Gemini 2.5 Pro）

**OpenRouter**:
- 输入OpenRouter API Key（格式：`sk-or-...`）
- **自定义模型**：在"模型"输入框中直接输入OpenRouter模型ID（例如：`anthropic/claude-3.5-sonnet`）
- **快捷选择**：点击下方"常用模型"按钮快速选择常用模型
- 推荐模型：Claude 3.5 Sonnet、GPT-5.2、Gemini 2.5 Flash

##### 2.1 配置管理

工具支持配置缓存和导入导出功能：

**配置缓存**:
- 配置自动保存到浏览器本地存储
- 刷新页面后自动加载之前的配置
- 支持的配置项：
  - AI提供商选择
  - 各提供商的API Key和模型
  - 自定义提示词

**导出配置**:
- 点击配置标题栏的"导出"按钮
- 下载JSON格式的配置文件
- 文件命名：`exercise-library-fixer-config-YYYY-MM-DD.json`
- 用于备份或在不同设备间共享配置

**导入配置**:
- 点击配置标题栏的"导入"按钮
- 选择之前导出的JSON配置文件
- 配置自动应用到界面并保存到缓存

##### 3. 导入运动库数据

在"导入数据"区域点击"选择文件"按钮，选择包含运动库数据的ZIP文件。

点击"加载文件"按钮，工具会自动解析ZIP中的exercise*.json文件。

##### 4. 扫描问题

点击"扫描问题"按钮，工具会自动分析每个运动项目，识别所有问题。

扫描完成后会显示：
- 问题总数
- 每个运动的问题详情
- 问题字段和具体描述

##### 5. 自动修复

点击"自动修复"按钮，AI会根据运动名称和分类自动补充或修正信息。

修复过程：
- 逐个处理有问题运动
- 根据运动特征推断正确的数据
- 更新运动信息

##### 6. 查看修复结果

使用顶部的过滤标签切换视图：
- **全部**: 显示所有运动
- **有问题**: 只显示还有问题的运动
- **已修复**: 只显示已修复的运动

每个运动卡片显示：
- 运动名称
- 运动类型和身体分类
- 问题状态（正常/有问题）
- 难度和设备信息

**点击运动卡片**可展开查看详细信息：
- 检测到的问题列表
- 修复后的数据（分类、肌肉群、内容描述）
- 动作教程（如果已生成）

##### 7. 单独修复

在展开的运动卡片中，点击"修复此运动"按钮，可以单独修复该运动的问题。

- 只修复当前运动，不影响其他运动
- 使用AI自动补充缺失或错误的信息
- 修复后会显示"数据完整"状态
- 修复后的数据会自动标准化（肌肉群使用标准值）

##### 8. 自定义教程提示词

在页面顶部的"自定义提示词"区域，可以输入自定义的提示词来自定义教程生成。

- 留空：使用默认的提示词模板（包含动作作用、发力心法、注意事项、常见错误）
- 自定义：输入自定义提示词，AI会使用该提示词生成教程
- 自定义提示词会应用到所有教程生成操作

##### 9. 生成教程

在展开的运动卡片中点击"生成教程"按钮，AI会为该运动生成详细的HTML格式教程，包含：
- 🎯 动作作用：锻炼的肌肉群、身体益处、适用人群
- 💪 发力心法：发力顺序、姿势细节、发力感觉、呼吸配合
- ⚠️ 注意事项：准备工作、关键要点、恢复建议、训练建议
- ❌ 容易做错的地方：常见错误、错误原因、纠正方法

教程生成后会显示在卡片中，并标记为"有教程"。

##### 10. 导出数据

修复完成后，点击"导出数据"按钮，下载修复后的JSON文件。

导出的文件包含：
- 生成时间戳
- 运动总数
- 已修复数量
- 完整的运动库数据
- 动作教程（如果已生成）

#### AI修复能力

AI可以根据运动名称自动补充以下信息：

1. **分类**: 判断运动属于哪个具体分类
2. **内容描述**: 生成详细的HTML格式运动说明
3. **运动类型**: 识别是力量训练还是有氧运动
4. **身体分类**: 判断主要锻炼的身体部位（胸部/肩部/手臂/背部/核心/腿部/臀部）
5. **肌肉群**: 准确识别主要肌肉群、次要肌肉群和稳定肌群，使用项目标准值
6. **设备要求**: 判断运动所需的设备
7. **难度**: 评估运动的难度等级

#### 标准数据格式

工具使用项目的标准数据格式，确保数据一致性：

**身体分类标准值**:
- 胸部、肩部、手臂、背部、核心、腿部、臀部、全身

**肌肉群标准值**（19个标准分区）:
- 上胸、中下胸（胸部）
- 背部、下背、斜方肌（背部）
- 前束、中束、后束（肩部）
- 二头、三头、小臂（手臂）
- 腹肌、侧腹（核心）
- 股四、腘绳、小腿（腿部）
- 上臀部、下臀部（臀部）

**肌肉群别名映射**:
工具会自动将常见别名映射到标准值，例如：
- "胸" → "中下胸"
- "肱二头肌" → "二头"
- "臀" → "上臀部"
- "大腿" → "股四"

#### 提供商选择建议

| 提供商 | 优点 | 缺点 | 适用场景 |
|--------|------|------|----------|
| **OpenAI** | 准确度高，稳定性好 | 价格较高 | 追求最高准确度 |
| **Gemini** | 性价比高，速度快 | 部分模型为实验版 | 大批量处理 |
| **OpenRouter** | 模型选择多，灵活性强 | 需要额外账户 | 需要特定模型时 |

#### 注意事项

1. **API Key安全**: API Key仅在本地使用，不会上传到任何服务器
2. **网络要求**: 使用AI修复功能时需要网络连接
3. **浏览器兼容**: 建议使用现代浏览器（Chrome、Firefox、Safari、Edge）
4. **数据备份**: 修复前请备份原始数据
5. **人工审核**: AI修复后建议人工审核修正结果
6. **实验模型**: Gemini的实验版本模型可能不稳定，建议使用稳定版本进行生产环境使用

#### 技术说明

- 纯前端实现，无需服务器
- 使用JSZip库解析ZIP文件
- 使用Tailwind CSS进行样式设计
- 支持响应式布局，适配移动端
- 使用Font Awesome图标库

### 3. 端口管理器 GUI (`port-manager-gui.html`)

一个可视化的项目端口管理工具，提供图形化界面来监控和管理开发服务端口。

#### 功能特点

- **可视化监控**: 实时显示所有项目端口状态（运行中/空闲）
- **进程信息**: 显示占用端口的进程 PID 和进程名称
- **一键关闭**: 快速终止占用端口的进程
- **命令执行**: 在 GUI 中直接执行系统命令（仅独立模式）
- **启动命令**: 显示各服务的启动命令，支持一键复制
- **自动刷新**: 支持自动刷新端口状态
- **自定义查询**: 支持检测任意端口的状态
- **独立模式**: 无需后端服务即可使用

#### 支持的服务端口

| 服务 | 端口 | 说明 |
|------|------|------|
| 前端 Vite | 43112 | npm run dev |
| 后端 API | 43111 | cd backend && npm run dev |
| LangGraph Studio | 43110 | cd backend && npm run studio |
| 端口管理器 | 43113 | 独立管理服务器 |
| PostgreSQL | 5432 | 数据库服务 (系统保护) |
| Docs 文档站 | 5173 | npm run docs:dev |

#### 端口状态说明

- **● 运行中**: 绿色，端口有进程占用，显示 PID 和进程名
- **○ 空闲**: 灰色，端口未被占用
- **▲ TIME_WAIT**: 黄色，端口处于释放等待状态
- **● 权限不足**: 红色，无法关闭的进程（如 PostgreSQL）

#### 启动方式

##### 方式一：双击启动（最方便）

双击项目根目录的 **`启动端口管理器.bat`** 文件即可启动。

或在 `docs/小工具/` 目录中双击 **`启动端口管理器.bat`** 文件。

##### 方式二：npm 命令

```bash
# 完整命令
npm run port-manager

# 简写别名
npm run pm
```

##### 方式三：直接运行脚本

```bash
node .claude/skills/port-manager/port-manager-server.mjs
```

#### GUI 功能说明

##### 查看端口状态

工具会自动加载并显示所有项目端口的状态卡片。

##### 关闭端口进程

- 对于正在运行的端口，点击"关闭"按钮
- 系统会终止该端口上的所有进程
- PostgreSQL 端口受系统保护，不允许关闭

##### 执行系统命令

在"执行系统命令"区域：
- 输入任意 Windows 命令并点击"执行"
- 使用快捷按钮快速执行常用命令
- 查看命令执行结果

##### 获取启动命令

- 对于空闲的端口，点击"启动命令"按钮
- 在弹出的对话框中查看启动命令
- 点击"复制命令"将命令复制到剪贴板

##### 自动刷新

- 点击右上角的"自动刷新"开关启用/禁用
- 启用后每 3 秒自动刷新端口状态

##### 自定义端口检测

- 在"自定义端口查询"区域输入端口号
- 点击"检测"按钮查看端口状态
- 如果是项目预设端口，会显示详细信息

#### 技术说明

- 纯 HTML 前端实现，通过 API 获取端口状态
- 独立服务器模式使用内置 Node.js HTTP 服务器
- 后端 API 模式: `/api/admin/ports/status`, `/api/admin/ports/kill`
- 使用 Windows 命令行工具（netstat, tasklist, taskkill）
- 仅支持 Windows 开发环境

#### 安全提示

- 端口管理功能仅在开发环境可用
- 请谨慎使用"关闭"功能，避免终止重要进程
- 独立服务器模式仅限本地访问
- 命令执行功能有安全限制，禁止危险操作
