# Web App Testing（Playwright）

## 适用场景

- 验证训练执行页、多态卡片渲染、管理控制台关键流程
- 修复 UI bug 后需要做回归保护
- 弱网/离线相关问题需要端到端复现与验证

## 本仓库约束

- 端到端测试入口：根目录 `npm run e2e`
- 需要先通过类型检查：根目录 `npm run typecheck`

## 工作流

### 1) 明确要测的用户路径

- 起点页面、核心交互、预期 UI 状态
- 关键断言：可见性、文案、请求/响应、副作用（如 Outbox 队列变化）

### 2) 优先用最少断言锁定行为

- 只断言“必要结果”，避免过度耦合实现细节
- 对动态内容，优先断言结构与关键字段，而非完整文本

### 3) 复用现有测试辅助能力

- 优先在 `e2e/` 现有结构内新增/调整
- 对跨页面流程，抽取 helper，避免重复编写登录/初始化逻辑

### 4) 失败时的定位策略

- 先确定失败类型：选择器不稳定 / 等待条件不足 / 接口响应不符合预期 / 数据前置条件缺失
- 优先把失败最小化：只保留能稳定复现的步骤
- 需要追踪 MAS 行为时，联动 `langsmith-fetch` 技能抓取 trace

## 输出要求

- 给出新增/更新的测试用例覆盖的用户路径
- 给出测试失败时的最小复现与定位结论（若存在）
