# MCP Builder

## 适用场景

- 需要将外部系统接入到 IDE/Agent 工作流（例如第三方 API、内部服务、知识库）
- 需要为 MAS 增加可控的工具能力，并保证权限边界与审计

## 设计约束（针对本仓库）

- 新增能力优先放入既定的新架构路径（前端 `src/v2/`，后端对应 service 层）
- 避免在客户端直接访问 L3；需要通过后端服务或既定 RPC/网关模式
- 对输入输出进行严格校验与降级（Zod 宽容解析 + UNKNOWN 枚举容错）

## 工作流

### 1) 定义最小工具面

- 明确要暴露的工具集合（tool names）、参数 schema、返回 schema
- 明确权限边界：只读/可写、是否需要 HITL 确认、是否会触发敏感操作

### 2) 选择实现语言与运行方式

- TypeScript 优先：便于与当前 Node/TS 栈一致
- 需要隔离/高频计算：考虑 Worker 或服务端异步任务

### 3) 增加防御性策略

- 超时、重试、背压、速率限制
- 日志与可观测性：必要时对接 LangSmith/Sentry（避免泄露敏感信息）

### 4) 验证与回归

- 为每个工具提供最小验证用例（单测/contract test/E2E）
- 对失败路径（鉴权失败、网络失败、上游 schema 变化）提供稳定降级

## 输出要求

- 输出 MCP server 的工具清单与 schema（可复制）
- 输出安全边界与测试计划
