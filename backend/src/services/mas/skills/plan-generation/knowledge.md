# 计划生成知识指南 (Plan Generation Knowledge Guide)

> 本指南由 Starfit MAS 系统维护，基于当前运动科学研究和最佳实践设计。
> AI Agent 在生成训练计划时应参考本指南，确保计划的科学性和安全性。

---

## 一、动作选择原则

### 1.1 复合动作优先原则

- **复合动作占比**：60-70% 的训练量应来自复合动作
- **优先级排序**：
  1. 大肌群复合动作（深蹲、卧推、硬拉、引体向上、划船）
  2. 多关节孤立动作（侧平举、弯举、三头下压）
  3. 单关节孤立动作（飞鸟、腿屈伸）

### 1.2 推拉腿平衡原则

- **推类训练日**：胸部、肩部、肱三头肌
- **拉类训练日**：背部、肱二头肌、后肩
- **腿部训练日**：股四头肌、腘绳肌、臀部

### 1.3 动作多样性原则

- 每周避免完全相同的训练组合
- 相同肌群使用不同角度刺激（如上斜/下斜卧推）
- 每 4-6 周轮换动作变式

## 二、容量分配规则

### 2.1 每周训练量指南

根据训练水平分配每周组数：

| 健身等级 | 每肌群周组数 | 说明 |
|---------|-------------|------|
| 初学者 (0-6个月) | 3-5 组 | 专注动作模式学习 |
| 中级 (6-24个月) | 6-10 组 | 渐进超负荷阶段 |
| 高级 (24+个月) | 10-15 组 | 精细化容量管理 |

### 2.2 单次训练容量

- **复合动作**：3-5 组
- **孤立动作**：3-4 组
- **核心训练**：3-4 组

### 2.3 次数范围与训练目标

| 训练目标 | 推荐次数范围 | 强度 (%1RM) | 间歇时间 |
|---------|-------------|------------|---------|
| 力量 (Strength) | 3-6 次 | 85-95% | 3-5 分钟 |
| 增肌 (Hypertrophy) | 8-12 次 | 65-80% | 60-90 秒 |
| 耐力 (Endurance) | 15-20 次 | 50-65% | 30-60 秒 |

## 三、重量推算逻辑

### 3.1 有历史记录的情况

当用户有历史负荷锚点时：

1. **使用历史 1RM**：训练重量 = 历史 1RM × 80%
2. **使用历史最佳重量**：训练重量 = 历史重量 × 85-95%
3. **递增规则**：每周增加 2-5%

### 3.2 无历史记录的推算

根据动作类型和用户体重推算：

| 动作类型 | 推算公式 | 说明 |
|---------|---------|------|
| 深蹲 | 体重 × (0.4-0.6) | 初学者取下限 |
| 卧推 | 体重 × (0.4-0.6) | 女性取下限 |
| 硬拉 | 体重 × (0.5-0.7) | 需要更强的基础 |
| 上肢孤立 | 体重 × 0.1-0.2 | 弯举、侧平举等 |
| 下肢孤立 | 体重 × 0.2-0.3 | 腿屈伸、腿弯举 |
| 自重动作 | 0 kg | 俯卧撑、引体向上 |
| 器械动作 | 哑铃 × 0.7-0.8 | 通常比自由重量轻 |

### 3.3 特殊情况

- **伤病恢复期**：使用常规重量的 50-70%
- **首次训练**：使用推算重量的 70% 作为试探
- **器械不熟悉**：降低 20% 以确保安全

## 四、三大项科学计算

### 4.1 识别三大项

以下动作需要使用 `calculate_capacity` 工具：

- **深蹲类**：深蹲、颈前深蹲、箱式深蹲
- **卧推类**：卧推、上斜卧推、地板卧推
- **硬拉类**：硬拉、罗马尼亚硬拉、六角杠硬拉

### 4.2 MEV/MRV 概念

- **MEV (Minimum Effective Volume)**：最小有效容量
  - 低于此值无法获得训练适应
- **MRV (Maximum Recoverable Volume)**：最大可恢复容量
  - 超过此值恢复不足，有过度训练风险

### 4.3 使用 calculate_capacity

三大项必须调用 `calculate_capacity` 工具，输入参数：

- 性别、体重、身高分类
- 力量等级、训练经验
- 年龄、饮食、睡眠、压力
- 历史训练容量和恢复能力

工具返回：推荐组数、次数范围

## 五、自定义动作规范

### 5.1 何时允许自定义动作

在以下情况下，Agent 可以创建自定义动作：

1. **动作库不足**：没有合适的动作匹配
2. **特殊需求**：用户有明确的康复或功能训练需求
3. **器械限制**：用户只有特定器械，动作库无匹配

### 5.2 创建新动作（必须使用 create_exercise 工具）

当动作库中没有合适的动作时，必须使用 create_exercise 工具创建：

**创建步骤**：
1. 调用 `load_skill({ skillName: "exercise_creation" })`
2. 使用 `create_exercise` 工具创建动作，获取 NanoID
3. 在计划中使用返回的 NanoID

**使用 create_exercise 的好处**：
- 创建的动作会保存到数据库，可复用
- 自动生成合法的 NanoID
- 支持向量索引，后续可被搜索到

**禁止使用 custom_ 前缀**：
- 不接受 `custom_` 前缀的 id
- submit_plan 验证会拒绝此类动作

### 5.3 自定义动作限制

- 禁止创建高风险动作（颈后推举、早安式等）
- 自定义动作优先使用低负荷、低风险
- 明确标注动作来源（"用户自定义"）

## 六、格式验证规则

### 6.1 字段验证

| 字段 | 类型 | 有效范围 | 必填 |
|------|------|---------|------|
| id | string | NanoID (12-24 chars) | 是 |
| name | string | 任意非空 | 是 |
| exercise_type | string | resistance/cardio/isometric/outdoor | 是 |
| sets | number | 1-20 | 是 |
| reps | number | 1-200（整数） | 是 |
| weight | number | >= 0 | 否 |
| duration | number | > 0（秒） | 视类型 |
| distance | number | > 0（米） | 视类型 |

### 6.2 常见错误及修正

| 错误 | 修正方法 |
|------|---------|
| sets > 20 | 限制为最大 20 组 |
| reps > 200 | 限制为最大 200 次 |
| reps 使用字符串 "8-12" | 必须使用整数，如 12 |
| weight < 0 | 设置为 0（自重） |
| 缺少 exercise_type | 设置为 resistance/cardio/isometric/outdoor 之一 |

  ```typescript

  submit_plan({
    exercise_list: [  // ← 参数名必须是 exercise_list，不是 plan
      { id: "V1StGXR8_Z5jdHi6", name: "杠铃深蹲", exercise_type: "resistance", sets: 4, reps: 12, weight: 60 }
    ],
    explanation: "训练计划说明"
  })
  ```

验证失败时，工具返回详细错误信息，Agent 应：
1. 修正错误字段
2. 重新调用 submit_plan
3. 重复直到验证通过

## 七、用户画像适配

### 7.1 健身等级适配

| 等级 | 训练重点 | RPE 范围 | 频率 |
|------|---------|---------|------|
| 初学者 | 动作模式学习 | 6-7 | 3 天/周 |
| 中级者 | 渐进超负荷 | 7-8 | 4 天/周 |
| 高级者 | 强度波动 | 8-9 | 5 天/周 |

### 7.2 训练目标适配

- **增肌期**：8-12 次，3-5 组，60-90 秒间歇
- **力量期**：3-6 次，5 组，3-5 分钟间歇
- **减脂期**：12-20 次，3-4 组，30-60 秒间歇

### 7.3 器械限制适配

- **仅哑铃**：增加单侧训练，注意弱侧平衡
- **仅器械**：增加孤立动作，控制节奏
- **自重为主**：增加次数，减少间歇

## 八、安全协议

### 8.1 红线停止条件

出现以下情况必须停止训练：

- 关节刺痛、肿胀、活动受限
- 头晕、恶心、心悸
- 力量突然下降 > 30%
- 技术动作明显变形

### 8.2 动作标准

- **核心激活**：所有负重动作前呼气沉肋
- **肩胛稳定**：推类动作肩胛骨下沉收拢
- **脊柱中立**：避免过伸或过屈

### 8.3 呼吸节奏

- 离心阶段：3 秒缓慢下放
- 底部停顿：1 秒消除惯性
- 向心阶段：1 秒爆发用力

## 九、输出格式规范

### 9.1 submit_plan 调用格式

训练计划完成后必须通过 submit_plan 工具提交验证：

```typescript
submit_plan({
  exercise_list: [  // ← 参数名必须是 exercise_list，不是 plan
    {
      id: "V1StGXR8_Z5jdHi6",
      name: "杠铃深蹲",
      exercise_type: "resistance",
      sets: 4,
      reps: 8,    // ← 必须是整数，不能是 "8-12"
      weight: 60
    }
  ],
  explanation: "这是一套全身增肌训练计划..."
})
```

**常见错误**：
- ❌ 参数名使用 `plan` 而非 `exercise_list`
- ❌ 将 exercise_list 值写成嵌套的 JSON 字符串
- ❌ reps 使用字符串 "8-12" 而非数字 12
- ✅ exercise_list 直接传递数组对象
- ✅ reps 必须是整数（如 12），不能是范围字符串

### 9.2 uiHint 结构（系统内部使用）

submit_plan 验证通过后，系统会自动构建 uiHint：

```json
{
  "type": "plan_card",
  "data": [...],
  "diff": {
    "added": ["V1StGXR8_Z5jdHi6"],
    "modified": [],
    "removed": []
  }
}
```

### 9.3 uiHint 结构详解

| 字段 | 类型 | 说明 |
|------|------|------|
| type | "plan_card" | 固定值 |
| data | ExercisePlan[] | 动作数组 |
| diff | PlanDiff | 变更记录 |

### 9.4 explanation 编写指南

**推荐结构**：
- 训练目标
- 动作要点（3-5个）
- 重量安排
- 注意事项
- 鼓励语

**内容要求**：
- 根据用户健身水平调整语气
- 初学者提供更详细的说明
- 适当使用 Markdown 格式

## 十、用户画像最高宪法

### 10.1 最高宪法原则

用户画像是所有计划决策的最高约束条件。

**用户画像包含的约束**：
- fitness_level: 决定训练强度、容量、动作复杂度
- basic_info: 体重、身高、年龄影响重量推算
- preferences.method: 训练目标决定动作选择
- preferences.equipment: 器械限制是硬约束
- tags: 如 "fitness_level:beginner", "goal:muscle_gain"

### 10.2 自定义动作的画像约束

当动作库不足需要创建自定义动作时：
- 不得超出用户的器械限制
- 不得安排用户伤病部位的动作
- 重量、难度必须符合用户的 fitness_level

### 10.3 突破画像的后果

如果生成的计划突破了用户画像，submit_plan 验证将失败。
